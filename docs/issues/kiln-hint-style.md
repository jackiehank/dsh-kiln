# kiln-hint-style — 提示框只有一种：把原生 title 换成自绘样式

## 问题

同一页里并存**两种**悬浮提示：

| | 图的节点提示 | 其余 11 处（行标题、动作标题、刷新、焦点 chip、聚焦按钮、面包屑、图例行…） |
| --- | --- | --- |
| 实现 | 自绘 `.dkf-tip` | 浏览器原生 `title` 属性 |
| 样式 | 圆角、浮层阴影、跟随主题（深色也跟着变） | 系统样式：方角、固定浅色、不吃主题 |
| 行为 | 跟随鼠标、即时出现 | 约 1 秒延迟、位置由系统定 |
| 内容 | issue id + ask/最后动作 + 标题 | 只有一行纯文本 |

截图里就是这两种框并排的样子：上面那张是图里的（我们的样式），下面那张是悬停一行提交时弹的
（系统的白底方角框）。一个界面两套提示框，读起来像两个产品。

## 目标

- 只有一种提示框：`.dkf-tip`。所有提示都走它，样式/圆角/阴影/主题跟随只有一处定义。
- 定位复用同一个函数（`tipPlacement`，贴边翻转），不引入第二套坐标逻辑。
- 原生 `title` 全部下线——它会和自绘提示**同时**出现，等于一次悬停弹两个框。

## 边界

- 文案不变：原来 `title` 里写什么，提示里还是什么（多行的保留多行）。
- 不做交互式提示（不能点、不能选），不做富文本。
- 不接管图节点的提示逻辑（它有自己的 hover 状态与 `ask` 摘要，内容形态不同，但共用 `.dkf-tip` 与定位函数）。
- 不改列表密度、不改 hover 底色（那是 `kiln-ui-refresh` 里定过的）。

## 验收

- 渲染树里 `title` 属性数量为 0；提示一律走 `data-hint`。
- 只有一处 `.dkf-tip` 样式定义；两处使用（图 / 通用提示）共用它。
- 提示框在容器滚动、拖动、指针离开时都会消失，不会粘在屏幕上。
- 长标题、多行提示（仓库路径 + 快照时间）能正确换行，宽度不超过 320px。

## 收集：12 处原生 title 的清单

| # | 元素 | 文案 | 形态 |
| --- | --- | --- | --- |
| 1 | `.dkf-repo` | `<cwd>` + `快照：… · <时间>` | 两行 |
| 2 | `.dkf-refresh` | 重新读取 kiln 快照 | 单行 |
| 3 | `.dkf-focuschip` | 退出聚焦，回到全局（Esc） | 单行 |
| 4 | `.dkf-focusbtn`（issue 行 / 时间线行） | `聚焦 <id>（快捷键 f）` | 单行 ×2 |
| 5 | `.dkf-arow` | 点开看这条提交的详情 | 单行 |
| 6 | `.dkf-atitle`（时间线行 / 子行） | 完整标题 | 单行 ×2 |
| 7 | `.dkf-crumb` | 切到母 issue | 单行 |
| 8 | `.dkf-legend-row` | `<关系>` 或 `<关系>（当前视图没画这类关系）` | 单行 |
| 9 | `.dkf-strip` | 最近 12 个动作的清单 | 多行 |
| 10 | `.dkf-block` | `序. 动作 · 日期 · 标题` | 单行 |

合计 **12 个 `title` 属性 + 1 套自绘 `.dkf-tip`**（图节点）。

### 为什么不能反过来（全用原生）

原生 `title` 的样式由系统决定，CSS 完全碰不到：深色主题下它永远是浅底方角框，
和 `.dkf-tip` 并排就是两种产品；而且它**不会**因为自绘提示出现而消失——一次悬停弹两个框。

### 为什么用事件委托，而不是逐处传 props

12 个调用点散在 6 个组件里，逐个传 hint 状态要穿过 TimelinePanel → ActionRow → … 整条链。
改成：元素上只留 `data-hint="文本"`，根节点一个 `pointerover` 用 `closest('[data-hint]')` 找目标。

- 组件不需要知道提示机制，新增提示只写一个属性；
- 进入 / 离开 / 滚动 / 拖动都在根节点一处收口；
- 多行文案用真实换行 + `white-space:pre-line`，不需要额外的结构。

### 有意保留的行为差异

| | 图节点提示 | 文字提示 |
| --- | --- | --- |
| 延迟 | 0（悬停即出） | 260ms |
| 位置 | 跟随指针 | 进入时定位一次 |

图上的提示是读到 issue 内容的**唯一**途径（ask 摘要），慢一拍就打断阅读；
列表里的提示只是"这行被截断了，给你看全"，扫过时不该闪。260ms 取自"原生约 1s 太长、即时又太吵"。
