# 关系图在几十到上百节点时的可读性

## 背景

`kiln-relation-graph` 之后关系页能出真图了（`~/kiln`，58 issue / 73 边，截图见 issue 讨论）。
图能显示、点节点能聚焦、能缩放平移——**但“能看”和“读得懂”之间还差一层**：现在是一张横着
铺开的长图，缩到一屏就看不清 id，放到 100% 就得左右拖。

本条只谈**大规模下的可视化**，不改数据面，也不改“点节点 = 聚焦”的既定手势。

## 现象（都来自 `~/kiln` 实测）

| # | 现象 | 数字 |
| --- | --- | --- |
| 1 | **弱关联淹没了结构**：`relates-to` 占全部边的七成，图上都是横跨整屏的细线 | 53 / 73 = 73% |
| 2 | **近半节点只挂在弱边上**：有向边（`caused-by` / `blocks` / `part-of`）只碰到一半节点 | 26 / 58 被有向边触及 |
| 3 | **边缘节点多**：只连一条边的、完全孤立的，加起来占四成 | 度 1：18；度 0：6 |
| 4 | **宽高比失衡**：`flowchart LR` 在几百像素宽的侧栏里横向铺开；Pele 只在 < 640px 时自动转 TB | 最大度 9，平均度 2.5 |
| 5 | 边标签逐条重复（满屏 `relates to` / `caused by`），信息密度被稀释 | — |

结论：**问题不是“节点太多”，是弱边太多**。只留有向边时是 20 条 / 26 节点，是个能一眼看完的骨架。

## 目标

50–200 节点时仍然：一屏能看出骨架、能定位某个 issue、能看出焦点周围的一圈。

## 选项空间

| 方向 | 做法 | 代价 |
| --- | --- | --- |
| A 过滤 | 关系类型开关（默认只画有向边，或按强弱分层），一键“显示全部弱关联” | 容易让人以为关系不存在——需要显式计数“还有 53 条弱关联” |
| B 取景 | 默认全图不变；新增“只看焦点一跳”，或反过来默认 1 跳 + “展开全部” | 默认裁会丢掉“全景”，与上一条 issue 的假设 5 冲突，需重议 |
| C 布局 | 方向可选（LR / TB）；或按 domain 切 `subgraph` 减少跨域长边 | subgraph 会改布局；domain 只有 1 个时无效 |
| D 视觉 | 边标签只在该边与焦点/hover 相关时显示；弱边更细更淡；节点标签在小比例下退化 | 需要知道缩放比例，Pele 的 zoom 有 `scale` 可读 |
| E 交互 | hover 高亮邻域；双击节点以它为根重排；面包屑回退 | 双击与 Pele 自带的“双击缩放”冲突，要避让 |
| F 规模 | 超阈值时默认 1 跳 + 提示 | 与 B 合流 |

## 边界

- 不改数据面（仍是 `kiln graph --json` 的快照）；
- 背景布局仍不跳：**只有显式操作**（切取景、换根）才允许重排；
- 不引新依赖：布局能力已由 Pele 提供；
- 不为了好看伪造关系（不删边、不合并节点）。

## 验收草案

1. `~/kiln` 58 节点：默认视图下不看拖动也能读出“哪几个是枢纽”，且能一眼找到任意指定 issue；
2. 弱关联可一键显隐，隐藏时**明说**隐藏了多少条；
3. 聚焦后焦点一圈在屏幕上清晰可辨（现状是淡化到 22%，与外周区别够不够要看实图）；
4. 切焦点仍不重排（沿用上一条 issue 的验收）；
5. 100 节点的合成用例仍可交互（滚动/缩放不卡）。

## 待定

1. 默认视图：全图（现状）还是“有向骨架”？
2. 弱边的表达：默认隐藏、默认淡化、还是折成“+N”？
3. 是否要按 domain 分组，还是等仓库有多个 domain 再说；
4. hover 高亮邻域值不值得做（与“点节点 = 聚焦”会不会打架）。

## collect：度数分布与“只留有向边”的投影

命令（`~/kiln`，只读）：

```powershell
kiln graph --json   # nodes 58 / edges 73；逐边累计度数
```

| 指标 | 值 |
| --- | --- |
| 节点 / 边 | 58 / 73（平均度 2.5，最大度 9） |
| 度 0（孤立） | 6 |
| 度 1 | 18 |
| 度 2–3 | 17 |
| 度 ≥ 4 | 17 |
| 边类型 | `relates-to` 53、`caused-by` 19、`blocks` 1（无 `part-of`） |
| 有向边触及的节点 | 26 / 58 |

**投影**：只画有向边 → **20 条边 / 26 个节点**（边减 73%，节点减 55%）。
也就是说默认收窄不是“少画一点”，是把图从“一团”变成“一张骨架”——
剩下 32 个只挂在弱边上的节点，正好是“可折叠”的那一层。

副作用要一起记：这 32 个节点若默认不画，它们与任何东西的关系就看不见了。
所以过滤必须**显式**（开关 + “还有 N 条弱关联 / N 个节点”的计数），不能悄悄消失。

## 落地（apply）：先做方向（选项 C）

按“先看效果再决定”的顺序，只做了**布局方向可选**这一档（用户指定：屏幕可以垂直滚动）：

- 关系页顶部多一排「横向 / 纵向」，映射到 `flowchart LR` / `flowchart TB`；
- 方向进 `viewStates.graphDirection`，按仓库记忆，与取景一起恢复；
- 方向是**唯一**会改 mermaid 文本的操作（`buildMermaid(issues, relations, direction)`），
  因此也是唯一允许重排的显式操作——切焦点仍然只改 class；
- 换方向会重新 mount，**缩放会回到 fit**，这是预期的（换了布局，旧视口没有意义）。

测试：`plugin/test/render.mjs` 19 例（新增“方向只换方向词”——除首行外文本必须逐字相同，
防止换方向时连带改了节点/边）。

**没做**：选项 A（弱边过滤）、D（标签按需）、E（hover 高亮）。它们的取舍还挂在下面「待定」里。

## 落地（apply）：结构 / 全部（选项 A1）

第二次落地，做的是**默认只画有向关系**：

- 关系页图取景多一组「结构 / 全部」，默认**结构**：只画 `caused-by` / `blocks` / `part-of` /
  `supersedes`，无向的 `relates-to` 连同“只挂在它上面”的节点（按边端算，未被任何有向边触及的）
  一起收起；
- 收起时**必须报数**：图下一行「已隐藏 53 条弱关联（无向）、32 个只挂在弱关联上的 issue」，
  带一个「显示全部」按钮——不能让人以为关系不存在；
- 范围进 `viewStates.graphScope`，按仓库记忆；与方向一样属于显式重排；
- `buildMermaid(issues, relations, direction, scope)` 返回里带 `hidden: {edges, nodes}`，
  数字直接从同一份数据算出来，不另外数。

测试：`plugin/test/render.mjs` **20 例**（新增两条：结构取景不含 `---`、隐藏计数正确；
全部取景把弱边与孤立点放回来且不再提示隐藏）。

## test：在 `~/kiln` 的真实数据上验一遍

要紧的不是“算式对不对”，而是**插件自己生成的文本**（不是我在探针里另写一份）在真实仓库上是什么样。
做法：把 `kiln graph --json` 的快照塞进 `KilnView` 的假 React 里渲染出 `data-mermaid`，
再交给 vendored Pele 渲染，量包围盒与交叉：

| 取景 | 节点 | 边 | 画布 | 交叉 |
| --- | --- | --- | --- | --- |
| 结构（新默认） | 26 | 20 | 2578×468 | **0** |
| 全部（旧默认） | 58 | 73 | 4538×2018 | 112 |

- 结构取景的文本里**不含 `---`、不含 `relates-to`**——过滤发生在生成层，不是渲染后遮盖；
- 数字与 collect 里手写变体的测量完全一致（26/20、2578×468、0），说明实现与实验口径没漂；
- 高度 2018 → 468：`~/kiln` 的图从“要拖三屏”变成“一屏能看完”。

## test：聚焦一个只挂弱关联的节点，它自己会从图上消失

结构取景筛节点的口径是“被有向边触及”。焦点若正好是那 32 个只挂 `relates-to` 的节点之一：

- 焦点节点**不在文本里**（`n_c["c"]` 不存在）；
- 容器上仍挂着 `data-focus="c"`，`paintFocus` 只能淡化它的邻居，
  结果是“点了 c、图上找不到 c”；
- `~/kiln` 里这种节点有 32 个（55%），从列表取景聚焦后再切回图就会踩到。

用例：`plugin/test/render.mjs`「聚焦一个只挂弱关联的节点：它自己也必须在图上」，当前**失败**。
结论：结构取景需要一个“焦点优先”的例外——但**不能**让 mermaid 文本普遍依赖焦点
（那会让每次切焦点都重排，破坏 `kiln-relation-graph` 的验收）。

## 落地（apply）：焦点优先的例外

改法是**局部**放宽，不是让文本普遍跟着焦点变：

- `GraphPanel` 先判断“焦点被结构取景挡住了吗”（`touchesDirected`）；
- 挡住了就**这一次**按「全部」生成文本，并在图下说明「焦点 x 只挂在弱关联上，已临时按「全部」画」；
- 没挡住时文本与焦点无关——`kiln-relation-graph` 的“切焦点不重排”验收仍然成立；
- 点的还是同一个焦点：从列表聚焦一个弱关联节点、再切回图，不会再“点了它却看不见它”。

用例转绿（21 个渲染用例），并额外断言那句说明必须出现——临时放宽不能悄无声息。




## collect：四种减噪手段的实测（58 节点）

方法：同一张 `~/kiln` 图（58 节点 / 73 边），用 vendored Pele **在 Node 里直接 `render()`**
（不需要浏览器，跑的是插件里同一份代码），量三样：包围盒、边交叉数（节点中心连线近似，
共用端点的边不计）、渲染耗时。

| 策略 | 画布 | 交叉 | 节点 / 边 | 耗时 |
| --- | --- | --- | --- | --- |
| TB 全图（当前默认） | 4538×2018 | 112 | 58 / 73 | 20 ms |
| ＋紧凑间距（nodeSpacing 15 / rankSpacing 30） | 4087×1699 | 107 | 58 / 73 | 9 ms |
| ＋去边标签 | 3995×1680 | 98 | 58 / 73 | 5 ms |
| **只留有向边** | **2578×468** | **0** | **26 / 20** | 2 ms |
| 只留有向边 ＋ 无标签 | 2578×372 | 0 | 26 / 20 | 1 ms |
| LR 全图（对照） | 4243×2240 | 112 | 58 / 73 | 6 ms |

**结论：间距和标签各只值 10% 左右，过滤值一个数量级**——高度 2018 → 468，交叉 112 → 0。
换个说法：现在这张图的乱，73% 是 `relates-to` 造成的，调参救不了。

三条顺手量到的：

1. **`flowchart-elk` 等于没换**：同一张小图，`flowchart TB` 与 `flowchart-elk TB` 的节点坐标逐点相同
   → Pele 把它当同一套布局（`detectType` 认这个类型，但没有独立的 ELK 引擎）。**换 ELK 不是可选手段。**
2. **一跳很小**：任一节点为焦点时，子图中位 **3** 个节点、平均 3.5、最大 10。
   在 58 节点下“聚焦即收窄”几乎不损失上下文——最省事的取景规则。
3. **边能单独定位**：Pele 给每条边挂了 `data-id="L_<from>_<to>_<序号>"`（节点是 `data-id="<node>"`），
   所以“聚焦时只淡化无关边”是能做的。`kiln-relation-graph` 里“边没有抓手”的结论是错的，需回补。

复现（不进仓库，用完即删）：`kiln graph --json > graph.json`，再用 `plugin/lib/client.pele.js`
导出 `render()`，对同一份节点/边拼出不同变体逐条量。交叉数是直线近似，只用于同条件横比。

### 候选手段与代价

| 手段 | 实测效果 | 成本 | 风险 |
| --- | --- | --- | --- |
| **A1 默认只画有向边**，一键展开弱关联 | 交叉 112 → 0，高度 −77% | 低 | 必须显式说“隐藏了 53 条 / 32 个节点”，否则像关系不存在 |
| A2 按关系类型逐个开关（词表 5 组） | 同 A1，更细 | 中 | 5 个开关 + 状态记忆，控件比 A1 重 |
| **B1 聚焦即收窄到 1 跳** | 节点 58 → 3（中位） | 低 | 与“默认全图”冲突，得重议上一条 issue 的假设 5 |
| B2 超阈值才自动 1 跳（如 > 40 节点） | 小图不受影响 | 低 | 阈值是魔法数，要能手动推翻 |
| D1 边标签按需显示 | 交叉 −14%，画布 −12% | 低 | 布局仍会变（标签宽度影响 rank） |
| D2 紧凑间距 | 画布 −10% | 低 | 一行 frontmatter config |
| D3 聚焦时淡化无关边（`data-id`） | 纯视觉降噪 | 中 | 需回补 `kiln-relation-graph` 的限制 |
| E1 hover 高亮邻域 | — | 中 | 与“点节点 = 聚焦”并存，不冲突 |
| F 按 domain 分组 | 不适用 | — | `~/kiln` 只有 1 个 domain，等有多个再谈 |

**推荐顺序**：A1（一发就把图从“一团”变“骨架”，且可逆）→ D3（边跟着焦点走，纯视觉）
→ B2（只在超大图时兜底）→ D1/D2（调参，最后做）。
