# 行的展开与聚焦：点击该做什么，聚焦该怎么做

## 背景

`kiln-views-shared-focus`（`03dfacf` 起）把框架搭起来了：一个 tab 内三页（timeline / issue / relation），
共享一个焦点 issue，聚焦后三页同时收窄。但那一版把**所有点击都用在了聚焦上**——视图里没有“展开”，
想看某条 issue 的 action 只能去 timeline 里翻。

本条把两个动作拆开：**点击 = 在本页展开**，**聚焦 = 另一个统一手势**。

## 现状（对着 `plugin/lib/client.js` 核过）

| 位置 | 行 | 现在点下去做什么 |
| --- | --- | --- |
| timeline 行里的 issue 名 | 365 | 聚焦该 issue |
| issue 页整行 | 444 | 聚焦该 issue |
| relation 全域行的两端 | 468 / 474 | 聚焦那一端 |
| relation 焦点的面包屑 | 500 | 聚焦母 issue |
| relation 子 issue 行 | 521 | 聚焦子 issue |
| relation 分组行 / 弱关联行 | 540 / 565 | 聚焦邻居 |
| 头部 `焦点：x ×` | 674 | 清除聚焦 |

结论：**点行 = 聚焦**，没有第二种动作；所以“展开看细节”这件事目前只有切到 relation 页看邻居这一条路。

## 需求

1. **点击行 = 展开**，不是聚焦。issue 页点一行，行下展开该 issue 的全部 action：一行一个、时间倒序、
   带 title（像 `git log`），马上能读到每条提交在讲什么；
2. **聚焦 = 另一个手势，三页统一**；
3. 展开与聚焦互不干扰：展开不改变取景；聚焦不自动展开（除非点的是展开面板里的按钮）。

## 三种候选

### A. 行尾的“聚焦”按钮（hover / 键盘聚焦时出现）+ 行点击展开

- 点击行 = 展开收起；行尾一个 `⌖ 聚焦` 按钮 = 切焦点；头部 chip = 退出；
- 展开面板的头部再放一个同样的按钮（触屏 / 没 hover 时也够得着）；
- 键盘：列表内 `↑/↓` 走行（roving tabindex）、`Enter` 展开收起、`f` 聚焦、`Esc` 退出聚焦；
- 优点：两个动作在行上各自可见、点击区域分开、键盘有等价路径；
- 缺点：每行多一个控件；只靠 hover 出现时，触屏设备要靠展开面板里的那个。

### B. 双击 = 聚焦，单击 = 展开

- 优点：零新增控件；
- 缺点：**不可发现**；双击与文本选择冲突；触屏上双击语义含糊。

### C. `Ctrl/Cmd+点击` = 聚焦

- 优点：零 UI 成本，接近文件管理器习惯；
- 缺点：**完全不可发现**，只能当 A 的加速键，不能当唯一入口。

## 倾向

**A**。只读视图里最贵的成本是“用户不知道还能做什么”，A 把两个动作都摆在行上；B / C 只适合当快捷键，
不适合当唯一入口。

两个待定细节：

- 图标与文案：`⌖` 图标 + `聚焦`，还是干脆一个“只看这条”的文字按钮（更直白、更宽）；
- 展开策略：允许多行同时展开，还是同时只展开一行（accordion）。倾向同时只留一个，列表短、滚动位置稳。

## 问题

在“只有三页、没有搜索、只读”的约束下，展开与聚焦应该怎么分配到手势与控件上，才能既被发现、又不误触？

## 约束

- 只读、不落盘；焦点仍只存在内存；
- 不依赖右键菜单（宿主不保证提供）；
- 键盘可达，且与已有 tablist 约定一致（roving tabindex + 方向键）；
- 每行只加必要控件，保持一行的信息密度（58 条 issue 的仓库要一眼扫得完）。

## 验收标准

- issue 页点任一行，行下展开该 issue 的 action 列表：一行一条、时间倒序、每条显示 action 类型与 title；
- 展开不改变焦点，也不改变另两页的取景；
- 点行不再改变焦点；焦点只由“聚焦”控件或键盘命令触发；
- 三个页面用同一个聚焦控件（同图标、同位置、同行为）；
- `Esc` 退出聚焦；头部 chip 仍可点；
- 键盘：列表内方向键走行、`Enter` 展开收起、聚焦命令可达；
- 切页后展开态丢失可以接受（视图会卸载），但焦点要保留。

## 待验证

- 展开态要不要跨页保留（要保留就得提到组件外；仍是内存状态，不违反“不落盘”）；
- 无 hover 的设备上聚焦按钮是否常驻；
- 一行里放两三个控件后，信息密度是否还够。

## 假设（hypothesize 1）：点行展开，`⌖ 聚焦` 切焦点

用户定的三条：

1. 聚焦控件 = **准星图标 + “聚焦”文字**（`⌖ 聚焦`），不用纯图标；
2. 展开**同时只保留一个**（accordion），点同一行再点一次收起；
3. 展开态**跨页保留**，保持连贯性。

由此推出两个连带决定（否则自相矛盾）：

- **焦点与当前页也要一起记住**：切页会卸载视图，只记展开项而丢掉焦点，回来仍是断的；三者一起按仓库
  存在内存里，刷新页面才清空（仍不落盘）；
- **行不做成 `<button>`**：一行要同时承载“点开展开”和“点行尾控件聚焦”，做成 button 会嵌套 button；
  改为行 `tabIndex=-1` + 列表容器 `tabIndex=0` 的 roving 模式，避免几十个 tab 停靠点。

实现取舍（记录，不写进验收）：

- 键盘：列表内 `↑/↓` 走行、`Enter/Space` 展开、`f` 聚焦、`Esc` 退出聚焦；
- 聚焦按钮 `tabIndex=-1`（鼠标点得到，键盘走 `f`），hover 或行内聚焦时才显形；
- timeline 行展开的是**这条提交的详情**（完整 sha、第 n / m 步、refs、时间），不是 issue 的动作列表——
  后者在 issue 页做，避免两页说同一件事；
- relation 全域行是“边”、行主人不唯一，所以两端各给一个 `⌖ <id>` 端点按钮，不设行级展开。

## 边界（不做）

- 不做搜索框；
- 不做写操作、不做看板；
- 不引入右键菜单。
