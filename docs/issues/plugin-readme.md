# 根 README 改成插件 dsh-kiln 的说明书

## 背景

仓库现在有两份 README：

- 根 `README.md`（41 行）是**仓级**说明：形态、这个仓库怎么管 issue、依赖、目录。
  安装一句话指去 `plugin/README.md#安装`。
- `plugin/README.md`（198 行）是**技术深水区**：三页取数、双端缓存、7 槽行、文件表、已知边界。
  它同时是 npm 包页面。

用户决定：**根 README 改成插件 dsh-kiln 的说明文档**，三个页面（时间线 / issue / 关系）的截图
稍后由用户补。也就是说，根 README 要承担「这是什么、长什么样、怎么装、怎么用」，
而 `plugin/README.md` 继续做「怎么做、为什么这么做」。

## 现状的问题

1. 新用户从根 README **看不出这个插件长什么样、能干什么**：没有截图、没有三页说明、没有交互
   （焦点 / 搜索 / 筛选 / 快捷键），只能点进 198 行里自己翻。
2. 安装只有一行链接，而这恰恰是外部用户最先要的东西。
3. `plugin/README.md` 有两条已经过期的说法（`kiln-relation-direction` 之后没同步）：
   - 「part-of 作母/子分组与面包屑」——面包屑早删了，现在是 `父 issue` / `子 issue` 两个方向组；
   - 「行内带方向与关系名」——行内早就没有箭头和关系名了；
   - 末尾的「词表硬编码在 `GROUPS` 里」也应改成 `REL_SIDES`。

## 目标与验收

1. 打开根 README **30 秒**能回答：这是什么、长什么样、怎么装、怎么用。
2. **三张截图位**：时间线、issue、关系各一张，放在 `docs/screenshots/`，文件名
   `timeline.png` / `issue.png` / `relation.png`（用户稍后放）。
3. **三页各一段**：这一页看什么、数据从哪来。
4. **交互清单**：焦点（三页共享，`f` 聚焦 / `Esc` 退出）、搜索（停 120ms、`↑↓` / `⏎` / `Esc`）、
   筛选（issue 页领域 + 状态、时间线动作 + 领域）、hover 提示、刷新。
5. **安装三种途径**：GitHub Release 的 tgz（主）、`github:…#path:/plugin`、本地 checkout；
   要求写清（DSH 0.2.x、kiln v0.3.0+）。
6. **深水区不搬**：性能数字、缓存策略、行形状、已知边界留在 `plugin/README.md`，根 README 只留
   摘要 + 链接。
7. 顺手修掉 `plugin/README.md` 里那三条过期说法。

## 边界

- 不改代码；`plugin/README.md` 只修过期条目，不重写它的技术内容。
- 截图由用户提供，本轮只留位置与文件名。
- 根 README 保留「这个仓库用 kiln 管 issue」这件事（它也是插件自己的活样本），但压到「开发」一节。

## 落地（apply）：根 README 变成插件说明书

`README.md` 从 41 行的仓级说明改成 128 行的插件文档，顺序按「读者会问的顺序」排：

1. 一句话定位 + 只读边界；
2. 三张截图位（`时间线` / `issue` / `关系`，各一句小标题）；
3. **三页表**：每页看什么、怎么筛；
4. **安装**：Release tgz（主）→ `github:…#path:/plugin` → 本地 checkout，外加要求（DSH 0.2.x、kiln v0.3.0+）；
5. **用起来**：焦点（`f` / `Esc` / chip）、搜索（120ms、`↑↓` `⏎` `Esc`）、筛选、刷新、页头按宽度收缩、
   悬停提示；
6. **数据从哪来**：一张「视图 → kiln 命令」表 + 按需取数与 HEAD 缓存两段摘要，细节链接到
   `plugin/README.md`；
7. **已知边界**（四条）与 **开发**（目录树、测试数字、kiln 管 issue、形态结论链接）、**许可**。

死链与过期项：

- 截图尚未提供，三处 `![](docs/screenshots/*.png)` 现在指向空文件。新建
  [`docs/screenshots/README.md`](../screenshots/README.md) 写明文件名与建议尺寸，用户补图后即显示。
- `plugin/README.md` 修掉三条过期说法：`part-of 作母/子分组与面包屑` → 方向分桶（父/子、阻塞/被阻塞、
  由…引发/引发了）；`行内带方向与关系名` → 行内不再有箭头和关系名；`GROUPS` → `REL_SIDES`。
  顺手在「视图语义」末尾补了一句页头随侧栏宽度分档（`kiln-head-width`）。

**遗留**：Release 里的 tgz 仍是 **0.14.0**，不含 `kiln-relation-direction` / `kiln-head-width` 的改动。
README 的安装段写的就是 0.14.0 的文件名——下次发版（打个新 tag）之后要同步改这里的版本号。
