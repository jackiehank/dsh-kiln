# 边的淡化：线、箭头、标签要作为一条边整体淡

## 背景

`kiln-graph-readability` 收敛出两个视图（全局 / 聚焦），其中「全局」在**有焦点**时淡化圈外。
节点做到了，边只做了一半——用户实测：“边的淡化没做好”。

## 现象与证据

用 vendored Pele 渲染一张三节点图（`flowchart LR` + 三种边）后，`<svg>` 里的结构是：

```html
<g class="pele-edges" ...>
  <g class="pele-edge" data-id="L_n_a_n_b_0">      ← 线 + 箭头
  <g class="pele-edge" data-id="L_n_b_n_c_0">
  <g class="pele-edge" data-id="L_n_c_n_a_0">
</g>
<g class="pele-edge-labels" font-size="14">
  <g class="pele-edge-label" data-id="L_n_a_n_b_0"> ← 标签是**兄弟**节点，不在 .pele-edge 里
  <g class="pele-edge-label" data-id="L_n_b_n_c_0">
  <g class="pele-edge-label" data-id="L_n_c_n_a_0">
</g>
```

现在 `paintFocus` 只给 `.pele-edge` 加 `dkf-gedge-dim`，于是：

1. **线淡了、标签不淡**——`|caused-by|` 这类文字留在亮处，比不淡更乱；
2. 判定靠 `L_<from>_<to>_` 前缀匹配，**两端都在圈外才淡**；
   一旦 Pele 改了 id 形态（版本升级），前缀匹配会静默失效——要么全亮、要么全暗，没有兜底；
3. 反向情形也在：**焦点自身**在「聚焦」视图下没有 tier（整张图都是一圈），
   但「全局」视图里如果焦点节点恰好不在本次渲染的节点集（被无向开关挡住），边的判定会跟着错。

## 目标

一条边的**线、箭头、标签**作为整体淡 / 亮，且行为不依赖 `data-id` 的内部结构（尽量）。

## 备选方案

| # | 做法 | 代价 |
| --- | --- | --- |
| **A** | 收集“要亮的边”的 `data-id` 集合，对**同 id 的所有元素**（`.pele-edge` + `.pele-edge-label`）一起加/去 class；找不到任何边元素时**不淡化** | 依赖 id 存在（但现在同 id 是稳定的）；实现简单 |
| B | 不按边判定，改成“整层淡化”：一个 class 同时作用 `.pele-edges` 与 `.pele-edge-labels`，所有边一起淡，只保节点 | 丢信息：看不出焦点连着谁 |
| C | 用 mermaid 的 `linkStyle` 按序号上色（文本由我们生成，序号可控），聚焦时**重画** | 与「全局视图不重排」冲突，且 linkStyle 的序号与 Pele 的渲染顺序要对齐 |
| D | 聚焦时给边加 `classDef`/`class`，Pele 支持按 class 上色 | 同样要重画；且样式类只能静态，切焦点要重新生成文本 |

倾向 **A**：它保住「全局视图不重排」，也不要求我们复刻 Pele 的边渲染顺序。

## 验收

1. 全局视图、有焦点：无关边的**线与标签一起**变淡，视觉上不再有“亮标签挂在暗线上”；
2. 无关边的箭头一起淡（箭头在 `.pele-edge` 内，本来就会淡，回归用例要覆盖）；
3. 边元素找不到（Pele 升级导致）时**退化为不淡化**，且控制台/图下有一句说明，不静默；
4. 「聚焦」视图不受影响（该视图整张图都是一圈，不需要淡化）；
5. 切焦点仍是纯 class 操作，mermaid 文本逐字不变（沿用现有断言）。

## 待定

1. 无关边淡到多少：现在是 `.18`，与节点的 `.22` 要不要统一；
2. 要不要同时把标签的 `opacity` 与线分离（线更淡、标签更淡）——视觉上哪个更舒服要试；
3. 是否需要「边淡 / 只留节点」的第三档（方案 B 作为可选）。

## 落地（apply）：按 data-id 集合，而不是按元素类型

选了方案 A，并顺手改了一处规则：

1. **同 id 一起处理**：`paintFocus` 现在遍历 `.pele-edge, .pele-edge-label`，
   按 `data-id` 判定，线和标签各自加 class（`dkf-gedge-dim` / `dkf-gedge-label-dim`）。
   不再假设标签在哪一层，Pele 换结构也不会漏；
2. **规则从“一端在圈里”改成“两端都在圈里”**：原来的规则会让“邻居 → 圈外”的边保持亮，
   而那正是“亮线连着暗节点”的来源——现在亮着的边一定连着两个亮节点；
3. **三档透明度分开**：
   ```css
   .dkf-graph{--dkf-dim-node:.2;--dkf-dim-edge:.2;--dkf-dim-label:.2}
   ```
   默认都是 `0.2`，以后想单独调节点/线/标签，改一个变量即可，不用动 JS；
4. **兜底**：一条边元素都没认出来时，这一轮**不做淡化**，并在图下说明
   “Pele 可能改了 data-id 形态”——不静默地假装淡过。

测试：`plugin/test/run.mjs` **27 例**，新增两条用假 DOM 直接调 `paintFocus`：
线/标签同淡同亮、清空焦点全部恢复、认不出边时返回 0。
内部函数通过 `globalThis.__DSH_KILN_TEST__` 这个测试缝暴露（生产路径不受影响）。

## test：在 `~/kiln` 的 58 个焦点上验“亮边两端都亮”

做法：把真实快照喂给 `buildMermaid`（全局视图、关无向），用 Pele 渲染出真 SVG，
再从 SVG 里取出所有 `.pele-edge` / `.pele-edge-label` / `.pele-node` 的 `data-id` 拼成假 DOM，
调真的 `paintFocus`，然后检查两条不变量：

1. 任何**没被淡化**的边，两个端点节点都没被淡化；
2. 每条边的**标签与线状态一致**（要么一起淡、要么一起亮）。

结果：

```
焦点数=58  检查的边=1160  被淡化的边=1109
违反次数=0
```

（1160 = 每个焦点各看一遍全局视图里的边，58 个焦点累计。）

## 结论

边的淡化现在是一条规则、三个可调变量：

- **规则**：亮着的边必须两端都在焦点圈内；圈外的线与它的标签一起淡。这样“亮线连暗节点”不会再出现；
- **变量**：`--dkf-dim-node` / `--dkf-dim-edge` / `--dkf-dim-label`，默认都是 `0.2`，
  以后要单独调某类元素只改 CSS，不用碰 JS；
- **兜底**：认不出边元素（Pele 升级改 id 形态）就这一轮不淡化并说明，不静默。

仍然**没做**的两项照旧挂在 `kiln-graph-readability` 的结论里：标签门槛（语义缩放）与 hover 预览。
